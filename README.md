# Korea Rate-Pricing Model

**시장 가격에서 금통위 인상확률을 뽑아내는 모형입니다.** 미국의 CME FedWatch가 하는 일을
한국 시장에서, KOFR OIS 스왑 호가를 써서 합니다.

기준일 2026-08-28 현재, 기준금리 3.00%에서 10/22 인상확률 14.3%, 11/26 76.3%,
연말 내재 기준금리 3.226%입니다.

---

## 먼저 읽어야 할 한계 네 가지

이 모형을 쓰기 전에 아래를 알고 계셔야 합니다. 모르고 쓰면 틀린 결론을 냅니다.

**1. "확률"은 진짜 확률이 아닙니다.** 회의별 내재 인상폭 Δ를 25bp로 나눠 `[0,1]`로 자른
값입니다. 그래서 50bp 인상이나 인하를 구분하지 못하고, Δ가 음수면 그대로 0에 붙습니다.
2026년 통안 렌즈의 8월 확률은 157영업일 중 16일이 정확히 0.000이었는데, 이는
"시장이 0%로 봤다"가 아니라 계산이 경계에 붙은 것입니다.

**2. 확률을 더한 값은 확률이 아니라 기대 인상 횟수입니다.** 10%/60%와 35%/35%는 합이
같아도 전혀 다른 상태입니다(한 번도 안 올릴 확률이 36% 대 42%). 합계만 보면 이 차이가
가려집니다.

**3. 누적은 믿고 회의별 배분은 믿지 마십시오.** 호가를 최소 단위 하나씩만 흔든
몬테카를로에서 90% 대역이 가까운 회의 4%p, 먼 회의 22%p까지 벌어졌습니다. 연말 누적
내재금리는 잘 식별되지만, 그것을 10월과 11월로 쪼개는 일은 잡음에 묻힙니다.

**4. 적합 오차(RMSE)는 적합도이지 신뢰도가 아닙니다.** 회의가 가까울수록 좋아지고
(1주 이내 평균 0.29bp, 41~60일 전 0.69bp), 회의 직후에는 앞단 계약 안에 금통위가 없어
베이시스를 흡수하지 못해 커집니다. 곡선을 잘 맞춰도 배분 식별과는 별개입니다.

## 빠른 시작

```powershell
pip install -r requirements.txt

# 1) 자동 수집 (무인증)
python scripts/download_daily_rates.py         # 현물 금리 15종
python scripts/download_kofia_curves.py        # 민평 커브
python scripts/download_bok_policy_calendar.py # 금통위 일정·기준금리 이력

# 2) 인포맥스 단말 데이터는 수기 반입
#    rawdata/infomax/KOFR_OIS.xlsx 를 열어 재계산 후 같은 이름으로 저장
#    (D1 = TODAY() 라 조회 종료일이 자동으로 오늘이 됩니다)

# 3) 모형 실행
cd model/scripts
python m1_step_function.py     # 계단함수 — 회의별 내재 인상폭·확률 (핵심)
python m9_ktb_strip.py         # 국고 단기 스트립 (교차검증)
python m6_gap.py               # 통안-OIS 격차
```

전체 실행 순서와 모듈별 설명은 [`model/README.md`](model/README.md)에 있습니다.

## 무엇을 근거로 무엇을 주장하는가

**핵심 주장: 정책금리 기대는 스왑에서 읽어야 합니다.** 현물 금리에는 담보·수급 프리미엄이
섞여 있어서, 그것으로 확률을 재면 틀립니다.

근거는 세 가지입니다.

| 근거 | 어디서 나오나 |
|---|---|
| 2013~2026년 정례 금통위 125회 백테스트 (3분류 Brier) | `m5_backtest.py` |
| 통안-OIS 격차의 구조 분해 (프리미엄 대 반응 지연) | `m6_gap.py` |
| 한국은행 방법론(AFNS) 자체 재현·대조 | `m10_afns.py` |

2026-08-27 금통위(25bp 인상) 실측 결과가 이 주장을 뒷받침합니다. 회의 전일 인상확률은
**KOFR OIS 97.5% · 통안 23.1% · CD-IRS 인상 0%(인하 44.1%)** 였습니다. 2026년 인상기
두 회의만 떼면 Brier는 OIS 0.009, 통안 0.591, CD-IRS 1.337입니다.

다만 전 표본에서는 금투협 BMSI 서베이(0.128)가 가장 정확합니다. 시장 가격의 강점은
총점이 아니라 방향 전환점에서의 정보입니다.

## 다음 사이클로 넘길 때

회의 날짜는 코드가 아니라 **`config/model.json`** 에 있습니다.

```json
{
  "target_year": 2026,
  "assumed_future_nodes": ["2027-01-15", "2027-04-15", "2027-07-15"]
}
```

- `target_year` — 회의별 확률을 열로 기록할 연도. 그 해의 금통위는 캘린더에서 자동으로 읽습니다.
- `assumed_future_nodes` — 일정 미공표 구간의 가정 노드. 한국은행이 다음 해 일정을 공표하면
  이 목록을 비우고 `download_bok_policy_calendar.py`를 다시 돌리면 실제 회의로 대체됩니다.

백테스트 표본과 이벤트 스터디 표본은 **데이터가 있는 데까지 자동으로 늘어납니다.**
특정 시점의 기준선을 다시 뽑으려면 `SAMPLE_END=2026-08-07 python m5_backtest.py` 처럼
환경변수로 고정합니다.

## 환경 요구사항

- **Python 3.10 이상** (개발·검증은 3.14.0)
- **Windows** — Word 렌더 검수(`_verify_any.py`)와 Excel COM이 `pywin32`를 씁니다.
  모형 계산 자체는 플랫폼을 타지 않습니다.
- **연합인포맥스 단말** — `rawdata/infomax/` 갱신에 필요합니다. 단말이 없으면 저장소에
  담긴 스냅샷 시점까지만 재현됩니다.
- **폰트** — Word 리포트는 HY신명조·HY견고딕을 씁니다. 없으면 Pretendard, 그것도 없으면
  맑은 고딕으로 자동 대체됩니다(`model/word/_word_style.py`).
- **ECOS 인증키는 선택** — `scripts/download_daily_rates.py`는 무인증 내부 서비스를 씁니다.
  공식 OpenAPI를 쓰려면 `.env`에 `ECOS_API_KEY`를 넣으십시오(`.env.example` 참조).
  내부 서비스는 공식 API가 아니므로 언제든 막힐 수 있습니다.

## 알려진 약점

한계 네 가지 외에, 저장소를 쓰실 때 알아두실 것들입니다.

- **OIS 표본이 얇습니다.** 유효 관측 36회이고, 호가가 실질적으로 형성된 2024년 하반기
  이후로 좁히면 더 줄어듭니다. 2026년의 적중 2회를 일반화하기에는 이릅니다.
- **회의 직전에 유리한 구조입니다.** 회의가 하루 앞이면 1주 OIS가 해당 노드를 거의 직접
  가격합니다. 한 달 이상 남은 시점의 정확도는 별개 문제입니다.
- **CD-IRS 렌즈는 확률 도구로 부적합합니다.** 백테스트에서 전 국면 무정보 이하였습니다.
  변동금리 준거가 CD91이라 CD 경직성과 조달 스프레드가 정책기대를 덮습니다. 연말 누적의
  참고로만 쓰십시오.
- **2027년 구간은 가정입니다.** 금통위 일정 미공표로 분기 노드를 두고 수축을 겁니다.
  10개월 너머는 평균회귀 사전믿음이 지배하므로 추세로만 읽으십시오.
- **`model/codex_claude 비교.md`** 는 같은 문제를 독립 구현한 다른 분석과의 교차 감사
  기록입니다. 대조 대상 저장소는 이 저장소에 포함되어 있지 않아 문서 안의 `../codex/...`
  경로는 열리지 않습니다.
